01

Com funciona un directori

El mínim que cal saber abans de començar.

En una empresa, si cada ordinador té els seus usuaris locals, quan entra una persona nova cal crear-li el compte a cada equip. Un servei de directori guarda els usuaris i els grups en un sol servidor, i els equips i les aplicacions li pregunten a ell. Es crea l'usuari una vegada i pot entrar a qualsevol equip. Això és l'acreditació centralitzada.

Farem servir OpenLDAP, un servidor de directori lliure. Els clients hi parlen amb el protocol LDAP, pel port 389.

La informació s'organitza en un arbre

El directori és un arbre, el DIT. A dalt hi ha el domini. A sota, les unitats organitzatives (OU), que fan de carpetes. A les fulles, els usuaris i els grups. Aquest és l'arbre de l'empresa d'exemple d'aquesta guia:

dc=exemple,dc=asix                  ← el domini (l'arrel)
├── ou=Persones                     ← unitat organitzativa
│   ├── ou=Vendes
│   │   ├── uid=aprats              ← usuari: Anna Prats
│   │   └── uid=jgarcia             ← usuari: Jordi Garcia
│   └── ou=Magatzem
│       └── uid=mserra              ← usuari: Marta Serra
├── ou=Grups
│   ├── cn=comercials               ← grup
│   ├── cn=magatzem
│   └── cn=encarregats
└── ou=Serveis
    └── uid=escaner                 ← compte d'un aparell, no d'una persona

Cada entrada té un nom complet: el DN

El DN és el camí de l'entrada fins a l'arrel, separat per comes. És com la ruta d'un fitxer, però escrita al revés:

uid=aprats
,

ou=Persones

dc=exemple,dc=asix

L'arrel, el DN base, surt del nom del domini: cada part separada per punts es converteix en un dc.

Què guarda cada entrada

Cada entrada és una llista d'atributs (nom: valor). Les línies objectClass diuen quin tipus d'objecte és i, per tant, quins atributs ha de tenir obligatòriament:

ObjecteobjectClassAtributs obligatoris
Unitat organitzativaorganizationalUnitou
GrupposixGroupcn, gidNumber

Aquesta llista d'atributs es pot escriure en un fitxer de text amb format LDIF. És el que mostra el servidor quan li demanes el contingut, i el que faràs servir per crear usuaris des del terminal (secció 6).

Servidor

1Xarxa amb IP fixa

Ubuntu Server configura la xarxa amb netplan, a partir d'un fitxer .yaml de la carpeta /etc/netplan/. Primer mira com es diuen els adaptadors i quin fitxer tens:

$ ip -br a          # el 2n adaptador és el que no té IP
lo        UNKNOWN   127.0.0.1/8
enp1s0    UP        10.2.118.33/16
enp2s0    UP
$ ls /etc/netplan/
00-installer-config.yaml

El fitxer normalment és 00-installer-config.yaml; en algunes màquines és 50-cloud-init.yaml. Edita el que hi hagi; no en creïs un de nou. Hi trobaràs els adaptadors. Al segon, desactiva el DHCP i posa-hi la IP:

$ sudo nano /etc/netplan/00-installer-config.yaml
network:
  ethernets:
    enp1s0:              # 1r adaptador: no el toquis
      dhcp4: true
    enp2s0:              # 2n adaptador: afegeix aquestes línies
      dhcp4: false
      addresses:
        - 192.168.50.10/24
  version: 2

Si el 2n adaptador no hi surt, afegeix-lo amb el mateix sagnat que el primer. Només espais, mai tabuladors: el YAML és molt estricte.

$ sudo chmod 600 /etc/netplan/*.yaml
$ sudo netplan apply
$ ip -br a

Ara el 2n adaptador ha de mostrar la IP. Si netplan apply diu Cannot call Open vSwitch, és un avís sense importància.

2Nom de l'equip

$ sudo hostnamectl set-hostname ldap01
$ sudo nano /etc/hosts

A /etc/hosts afegeix una línia amb la IP, el nom complet (equip + domini) i el nom curt:

192.168.50.10   ldap01.exemple.asix   ldap01
$ hostname -f       # ha de mostrar ldap01.exemple.asix

3Instal·la i configura OpenLDAP

$ sudo apt update
$ sudo apt install slapd ldap-utils

slapd és el servidor; ldap-utils, les ordres per consultar-lo i modificar-lo.

La instal·lació demana una contrasenya i crea el directori amb un domini per defecte (normalment dc=nodomain), que no és el teu. Per posar-hi el teu domini, obre l'assistent complet:

$ sudo dpkg-reconfigure slapd

Administrator password (dues vegades)La contrasenya de l'administrador del directori

A partir del domini, l'assistent crea l'arrel dc=exemple,dc=asix i l'administrador del directori:

cn=admin,dc=exemple,dc=asix
+
la contrasenya de l'assistent
LA CONTRASENYA DE L'ADMINISTRADOR

La faràs servir a les tres pràctiques: per crear usuaris, per entrar a LAM... Apunta-la ara. Fes-la només de lletres i números: la consola d'Isard pot tenir el teclat en una altra distribució i els símbols no surten igual que quan després l'escrius al navegador. Si l'oblides, no tornis a fer dpkg-reconfigure si ja tens usuaris creats, perquè esborra el directori: mira la secció 3.

4Comprova que funciona

$ systemctl status slapd        # ha de sortir active (running)
$ sudo slapcat                  # mostra tot el contingut del directori
$ ldapwhoami -x -H ldap://localhost -D "cn=admin,dc=exemple,dc=asix" -W

slapcat mostra el directori en format LDIF. Ara només hi ha una entrada, l'arrel dc=exemple,dc=asix: és correcte, encara no hi has creat res. Si hi veus dc=nodomain, torna al pas 3.

ldapwhoami comprova la contrasenya de l'administrador. Si és bona, respon amb el seu DN (dn:cn=admin,dc=exemple,dc=asix). Si respon Invalid credentials (49), la contrasenya o el DN no són els que creus.

-H ldap://localhosta quin servidor et connectes
-D "cn=admin,..."amb quin usuari del directori t'identifiques
-Wque et demani la contrasenya

5Mira la configuració del servidor

La configuració d'OpenLDAP es guarda dins del mateix servidor, en una branca especial anomenada cn=config. No s'edita a mà: es consulta i es modifica amb les ordres LDAP. Aquesta ordre mostra on està definit el domini, l'administrador i qui pot llegir què:

$ sudo ldapsearch -Q -LLL -Y EXTERNAL -H ldapi:/// -b cn=config "(olcSuffix=*)" olcSuffix olcRootDN olcAccess
dn: olcDatabase={1}mdb,cn=config
olcSuffix: dc=exemple,dc=asix
olcAccess: {0}to attrs=userPassword by self write by anonymous auth by * none
olcAccess: {1}to attrs=shadowLastChange by self write by * read
olcAccess: {2}to * by * read
olcRootDN: cn=admin,dc=exemple,dc=asix
LíniaQuè vol dir
olcSuffixEl domini del directori
olcRootDNL'administrador. No és un usuari de l'arbre: està definit aquí, a la configuració. Per això slapcat no el mostra.
olcAccess {0}Les contrasenyes: cada usuari pot canviar la seva i serveixen per iniciar sessió, però ningú no les pot llegir
olcAccess {2}Tota la resta del directori la pot llegir qualsevol, fins i tot sense identificar-se

-Y EXTERNAL -H ldapi:/// vol dir: connecta't pel canal intern del servidor i identifica't com a root de la màquina. Per això no demana contrasenya, però només funciona amb sudo i al mateix servidor.

Client

6Xarxa i nom del client

A Ubuntu Desktop és més còmode per entorn gràfic: Paràmetres → Xarxa, engranatge de la connexió del 2n adaptador → IPv4 → Manual. Adreça 192.168.50.20, màscara 255.255.255.0, porta d'enllaç i DNS buits. Aplica, i desactiva i torna a activar la connexió.

$ sudo hostnamectl set-hostname pc01
$ sudo nano /etc/hosts

Afegeix-hi el servidor perquè el client el trobi pel nom:

192.168.50.10   ldap01.exemple.asix   ldap01
$ ping -c 3 ldap01

7Connecta el client al domini

Aquest és el pas que fa que el client faci servir els usuaris del directori. S'hi instal·la nslcd, un servei que pregunta al servidor LDAP en nom del sistema: quan algú inicia sessió, nslcd consulta si l'usuari existeix i si la contrasenya és correcta.

$ sudo apt update
$ sudo apt install libnss-ldapd libpam-ldapd ldap-utils

En instal·lar-los s'obre un assistent:

PreguntaQuè has de respondre
LDAP server URIldap://192.168.50.10/ (esborra el que hi hagi)
LDAP server search baseEl DN base: dc=exemple,dc=asix
Name services to configureMarca passwd, group i shadow amb la barra espaiadora i accepta amb Retorn
COMPTE

Si no marques shadow, en iniciar sessió el client dirà que la contrasenya és incorrecta. Si t'equivoques en alguna resposta, torna a obrir l'assistent: sudo dpkg-reconfigure nslcd (servidor i base) i sudo dpkg-reconfigure libnss-ldapd (serveis).

On queda cada cosa:

$ grep -E "^(uri|base)" /etc/nslcd.conf
uri ldap://192.168.50.10/
base dc=exemple,dc=asix
$ grep -E "^(passwd|group|shadow)" /etc/nsswitch.conf
passwd:         files systemd ldap
group:          files systemd ldap
shadow:         files systemd ldap

files ... ldap: el sistema busca primer els usuaris locals i, si no el troba, el pregunta al directori.

$ sudo systemctl restart nslcd

8Directori personal automàtic

Els usuaris del directori no tenen carpeta a /home del client. Sense carpeta, el sistema accepta la contrasenya i torna a la pantalla d'inici. Aquesta ordre fa que es creï sola el primer cop que l'usuari entra:

$ sudo pam-auth-update --enable mkhomedir
$ grep mkhomedir /etc/pam.d/common-session      # ha de sortir una línia amb pam_mkhomedir.so

9Comprova el client

$ ldapsearch -x -H ldap://192.168.50.10 -b "dc=exemple,dc=asix"

Si surt el mateix que veus amb slapcat al servidor, el client arriba al directori. Encara no hi ha usuaris al directori, així que getent passwd només mostrarà els locals. Quan en creïs (Part 2), hi apareixeran i s'hi podrà iniciar sessió.

03

Si oblides la contrasenya de l'administrador

Recuperar-la sense perdre res del que has creat.

És l'error més habitual. Abans de res, comprova-la al servidor:

$ ldapwhoami -x -H ldap://localhost -D "cn=admin,dc=exemple,dc=asix" -W

Si respon Invalid credentials (49) i estàs segur que el DN és bo, la contrasenya no és la que creus. Hi ha dues situacions:

SituacióQuè fer
El directori encara és buit (Pràctica 1)Torna a fer sudo dpkg-reconfigure slapd i posa una contrasenya nova. Ho torna a crear tot des de zero.
Ja hi has creat usuaris (Pràctiques 2 i 3)No facis dpkg-reconfigure: esborraria el directori. Canvia només la contrasenya amb els passos d'aquí sota.

1Genera la contrasenya xifrada

$ slappasswd
New password:
Re-enter new password:
{SSHA}2DYqIZsdNR/rRUQ/oZNOkpLxBvZviywj

Escriu la contrasenya nova dues vegades. Copia la línia que comença per {SSHA}: és la contrasenya xifrada.

2Escriu un fitxer amb el canvi

$ nano canvi-admin.ldif
dn: olcDatabase={1}mdb,cn=config
changetype: modify
replace: olcRootPW
olcRootPW: {SSHA}2DYqIZsdNR/rRUQ/oZNOkpLxBvZviywj

A l'última línia, enganxa la teva línia {SSHA}. olcRootPW és on el servidor guarda la contrasenya de l'administrador (al costat d'olcRootDN, que vas veure al pas 5).

3Aplica'l i comprova

$ sudo ldapmodify -Y EXTERNAL -H ldapi:/// -f canvi-admin.ldif
$ ldapwhoami -x -H ldap://localhost -D "cn=admin,dc=exemple,dc=asix" -W

Ara ldapwhoami ha d'acceptar la contrasenya nova. És la mateixa que faràs servir per entrar a LAM. No cal canviar res més: ni el client ni els usuaris fan servir la contrasenya de l'administrador.

04

Part 2 · Dissenyar el directori

Abans de crear res, es dibuixa l'arbre. Pràctica 2, part A.

Abans d'obrir LAM es decideix com serà l'arbre: quines OU hi haurà, quins grups, quins usuaris i amb quins números. Si es canvia després, canvien els DN i cal refer feina.

Criteris

  • Separa per tipus al primer nivell: una OU per a les persones, una per als grups i una per als comptes de servei. Així una aplicació pot buscar només persones.
  • Dins de les persones, una OU per departament, si l'empresa s'organitza així.
  • Nom d'usuari: inicial del nom + primer cognom, en minúscules i sense accents: Anna Prats → aprats.
  • Números: persones a partir de uidNumber 10001, grups a partir de gidNumber 20001 i comptes de servei a partir de 10100. Els usuaris locals de Linux comencen pel 1000: amb números alts no es barregen. LDAP no avisa si en repeteixes un, per això s'apunten al disseny.

Grup principal i grups secundaris

Cada usuari té un grup principal, que s'indica a l'usuari (gidNumber). Si a més ha de ser d'un altre grup (un grup secundari, per exemple un equip que agrupa gent de diversos departaments), s'indica al grup, amb una línia memberUid per a cada membre.

uid=aprats · gidNumber: 20001
→
grup principal: comercials
cn=encarregats · memberUid: aprats
→
grup secundari: encarregats

Comptes de servei

Un escàner o una aplicació que necessita un usuari propi no és una persona i no ha d'iniciar sessió enlloc. Va a la seva OU, amb shell /usr/sbin/nologin i sense contrasenya.

LDAP Account Manager (LAM) és una pàgina web que s'instal·la al servidor i que permet gestionar el directori sense escriure ordres. S'hi entra des del navegador del client.

1Instal·la LAM al servidor

$ sudo apt update
$ sudo apt install ldap-account-manager
$ systemctl status apache2       # LAM és una web: funciona amb Apache

Al navegador del client, obre http://192.168.50.10/lam.

2Les tres contrasenyes de LAM

A LAM hi ha tres contrasenyes i és fàcil confondre-les:

ContrasenyaQuan te la demanaValor
General (master)LAM configuration → Edit general settingslam
Del perfilLAM configuration → Edit server profileslam
Administrador LDAPA la pantalla d'inici de LAM, per entrar a treballarLa de l'administrador del directori (Part 1, pas 3)

Les dues primeres són de LAM i durant la pràctica les deixes com estan (lam). La tercera no és de LAM: és la del directori, i LAM només la comprova contra el servidor.

3Configura el perfil

LAM ve preparat per a un domini d'exemple (dc=my-domain,dc=com) que no és el teu. A la pantalla d'inici, fes clic a LAM configuration (a dalt a la dreta) → Edit server profiles → contrasenya lam.

COMPTE

Els noms dels menús canvien una mica segons la versió i l'idioma de LAM. Si no trobes un camp amb aquest nom exacte, busca'l per la funció.

4Entra com a administrador

A la pantalla d'inici, l'usuari ja surt (admin). Escriu la contrasenya de l'administrador LDAP, no lam. La primera vegada, LAM avisa que no existeixen les OU de persones i de grups i et proposa crear-les: accepta.

COMPTE

Si no et deixa entrar, prova la contrasenya al servidor amb ldapwhoami (Part 1, pas 4). Si allà funciona, el problema és del perfil: revisa List of valid users i Tree suffix. Si allà tampoc funciona, la contrasenya de l'admin no és la que creus: secció 3.

5Crea les OU i els grups

OU: a Tree view (vista d'arbre), selecciona l'OU pare i crea-hi una entrada nova de tipus unitat organitzativa. Les de primer nivell (Persones, Grups) potser ja les ha creat LAM al pas 4. Falten les de dins (Vendes, Magatzem) i Serveis. Sempre de dalt a baix: no es pot crear una OU dins d'una que encara no existeix.

Grups: pestanya Groups → New group. Escriu el nom i comprova que el gidNumber és el del disseny; si LAM en proposa un altre, canvia'l. Desa.

Suffix (desplegable, a dalt)L'OU del seu departament: ou=Vendes,ou=Persones,...
COMPTE

El desplegable Suffix. LAM posa cada usuari nou a l'OU general de persones. Si no el canvies a l'OU del seu departament abans de desar, tots els usuaris acaben al mateix lloc. Si et passa, es poden moure des de LAM.

Per fer que un usuari sigui membre d'un grup secundari (com encarregats): a l'usuari, pestanya Unix → Edit groups; o al grup, Members.

7Comprova

A Tree view, desplega tot l'arbre i compara'l amb el disseny. Al servidor:

$ sudo slapcat | grep "^dn:"

Part 2 · Crear i modificar amb fitxers LDIF

El mateix des del terminal. Pràctica 2, part C.

Al terminal, les entrades s'escriuen en un fitxer LDIF i s'envien al servidor. Serveix per fer moltes altes de cop o canvis repetibles. Tot es fa al servidor.

1Consulta abans d'escriure

Abans d'escriure el fitxer, demana al directori els DN exactes de les OU i els números que ja estan ocupats:

$ ldapsearch -x -LLL -H ldap://localhost -b "dc=exemple,dc=asix" "(objectClass=organizationalUnit)" dn
$ ldapsearch -x -LLL -H ldap://localhost -b "dc=exemple,dc=asix" "(objectClass=posixGroup)" cn gidNumber
$ ldapsearch -x -LLL -H ldap://localhost -b "dc=exemple,dc=asix" "(objectClass=posixAccount)" uid uidNumber

2Escriu el fitxer d'altes

Normes: cada entrada comença amb dn:; una línia per atribut; una línia en blanc entre entrades; cap espai al final de les línies.

$ nano alta.ldif
dn: uid=mserra,ou=Magatzem,ou=Persones,dc=exemple,dc=asix
objectClass: inetOrgPerson
objectClass: posixAccount
objectClass: shadowAccount
uid: mserra
cn: Marta Serra
givenName: Marta
sn: Serra
uidNumber: 10003
gidNumber: 20002
homeDirectory: /home/mserra
loginShell: /bin/bash

dn: uid=escaner,ou=Serveis,dc=exemple,dc=asix
objectClass: inetOrgPerson
objectClass: posixAccount
uid: escaner
cn: Escaner de la planta 1
sn: escaner
uidNumber: 10100
gidNumber: 20002
homeDirectory: /nonexistent
loginShell: /usr/sbin/nologin

3Afegeix-lo i posa contrasenya

$ ldapadd -x -H ldap://localhost -D "cn=admin,dc=exemple,dc=asix" -W -f alta.ldif
$ ldappasswd -x -H ldap://localhost -D "cn=admin,dc=exemple,dc=asix" -W -S "uid=mserra,ou=Magatzem,ou=Persones,dc=exemple,dc=asix"

ldappasswd demana tres contrasenyes, en aquest ordre: la nova de l'usuari (dues vegades, per -S) i la de l'administrador (per -W). Al compte de servei no se li posa.

4Modifica entrades

Per canviar una entrada que ja existeix, el fitxer porta changetype: modify i què fas amb cada atribut: add (afegir), replace (substituir; si no hi era, el crea) o delete (treure). Si canvies dues coses de la mateixa entrada, les separes amb una línia que només té un guionet -. Exemple: posar telèfon a la Marta i fer-la membre del grup encarregats.

$ nano canvis.ldif
dn: uid=mserra,ou=Magatzem,ou=Persones,dc=exemple,dc=asix
changetype: modify
replace: telephoneNumber
telephoneNumber: 934005566

dn: cn=encarregats,ou=Grups,dc=exemple,dc=asix
changetype: modify
add: memberUid
memberUid: mserra
$ ldapmodify -x -H ldap://localhost -D "cn=admin,dc=exemple,dc=asix" -W -f canvis.ldif
$ ldapsearch -x -LLL -H ldap://localhost -b "dc=exemple,dc=asix" "(cn=encarregats)" memberUid

5Comprova

$ sudo slapcat | grep "^dn:"

Les entrades creades amb LDIF també surten a la vista d'arbre de LAM.

ELS MISSATGES D'ERROR

El servidor explica què ha fallat. Els més habituals:

  • No such object (32): l'OU on vols crear l'entrada no existeix o el DN està mal escrit.
  • Already exists (68): l'entrada ja hi era.
  • Object class violation (65): falta un atribut obligatori; el missatge diu quin.
  • Type or value exists (20): afegeixes un memberUid que el grup ja tenia.
  • Invalid credentials (49): contrasenya de l'admin incorrecta (secció 3).

Comprovar que els usuaris del directori entren a l'Ubuntu Desktop. Pràctica 2, part D.

Part 2 · Buscar amb filtres

Trobar entrades concretes amb ldapsearch. Pràctica 2, part E.

Una cerca té quatre parts: des d'on busques, fins a quina profunditat, què busques i quins atributs vols veure.

$ ldapsearch -x -LLL -H ldap://192.168.50.10 -b "dc=exemple,dc=asix" -s sub "(objectClass=posixAccount)" uid cn
PartA l'exempleQuè vol dir
-b"dc=exemple,dc=asix"Des d'on: tot el domini
-ssubProfunditat: sub tot el que hi ha a sota (per defecte); one només el primer nivell; base només l'entrada de -b
filtre"(objectClass=posixAccount)"Què: els comptes Unix
atributsuid cnQuè vols veure de cada resultat. Si no en poses, surten tots

Com s'escriuen els filtres

FiltreSignificat
(uid=aprats)igual a
(telephoneNumber=*)té aquest atribut
(sn=G*)comença per G
(uidNumber>=10002)més gran o igual (també <=)
(&(...)(...))es compleixen totes
(|(...)(...))se'n compleix alguna
(!(...))no es compleix

El símbol (&, |, !) va davant de les condicions. Cada condició va entre parèntesis, i el filtre sencer també. Posa sempre el filtre entre cometes dobles.

Exemples

Què busquesFiltreResultat
Tots els comptes Unix"(objectClass=posixAccount)"aprats, jgarcia, mserra, escaner
Cognom que comença per G"(sn=G*)"jgarcia
Grups on aprats és membre secundari"(&(objectClass=posixGroup)(memberUid=aprats))"encarregats
Comptes sense telèfon"(&(objectClass=posixAccount)(!(telephoneNumber=*)))"aprats, escaner
Amb telèfon o que no poden iniciar sessió"(&(objectClass=inetOrgPerson)(|(telephoneNumber=*)(loginShell=/usr/sbin/nologin)))"jgarcia, mserra, escaner
UID 10002 o més i grup principal comercials"(&(uidNumber>=10002)(gidNumber=20001))"jgarcia

Buscar dins d'una sola OU

Per buscar només les persones de Vendes, es canvia -b, no el filtre. Les persones no tenen un atribut ou: l'OU forma part del seu DN.

$ ldapsearch -x -LLL -H ldap://192.168.50.10 -b "ou=Vendes,ou=Persones,dc=exemple,dc=asix" "(objectClass=posixAccount)" uid

Comptar resultats

$ ldapsearch -x -LLL -H ldap://192.168.50.10 -b "dc=exemple,dc=asix" "(objectClass=posixAccount)" dn | grep -c "^dn:"
NOMS AMB ACCENT

Si un nom té accents, ldapsearch el mostra codificat, amb dos punts dobles: cn:: TnXDunJpYSBSb2Nh. És normal. Per llegir-lo: echo TnXDunJpYSBSb2Nh | base64 -d.

Part 3 · Una web que fa servir el directori

Apache demana usuari i contrasenya i els comprova contra LDAP. Pràctica 3.

Moltes aplicacions poden fer servir el directori per identificar els usuaris: webs, correu, VPN, carpetes compartides... Així cada persona té un sol usuari i una sola contrasenya per a tot. Aquí ho farem amb Apache: una intranet on cada persona entra amb el seu usuari del directori i només veu les zones que li toquen.

Navegadorpc01
usuari + contrasenya
Apacheldap01
mòdul authnz_ldap
OpenLDAPldap01
port 389

Quan algú escriu el seu usuari, Apache fa tres coses: busca l'usuari al directori, comprova la contrasenya connectant-se al directori amb aquell usuari, i mira si té permís per a la zona que demana.

ZonaQui hi entra a l'exemple
/intranet/Qualsevol persona del directori
/intranet/vendes/Les persones amb grup principal comercials
/intranet/magatzem/Les persones amb grup principal magatzem
/intranet/encarregats/Els membres del grup secundari encarregats
/intranet/direccio/Només l'Anna
/intranet/telefons/Les persones de Vendes que tenen telèfon

1Activa el mòdul

Apache ja és al servidor: el va instal·lar LAM. Només cal activar-li el mòdul que parla amb LDAP:

$ sudo a2enmod authnz_ldap
$ sudo systemctl restart apache2
$ apache2ctl -M | grep ldap          # han de sortir authnz_ldap_module i ldap_module

2Crea les carpetes

$ sudo mkdir -p /var/www/html/intranet/{vendes,magatzem,encarregats,direccio,telefons}
$ echo "Intranet Distribucions Exemple" | sudo tee /var/www/html/intranet/index.html
$ echo "Zona vendes" | sudo tee /var/www/html/intranet/vendes/index.html

I el mateix per a cada zona, amb el seu nom.

3On busca Apache els usuaris

Es diu amb una sola línia, AuthLDAPURL, que té cinc parts separades per / i ?:

ldap://127.0.0.1
/
ou=Persones,dc=exemple,dc=asix
?
uid
?
sub
?
(objectClass=posixAccount)
PartQuè vol dir
ldap://127.0.0.1el servidor LDAP: és la mateixa màquina
ou=Persones,...on busca: només a les persones (els comptes de servei no hi són i no podran entrar)
uidel nom que escriu l'usuari es compara amb uid
subbusca a tots els nivells per sota
(objectClass=posixAccount)només comptes Unix

4Escriu la configuració

$ sudo nano /etc/apache2/conf-available/intranet-ldap.conf
<Directory /var/www/html/intranet>
    AuthType Basic
    AuthName "Intranet Distribucions Exemple"
    AuthBasicProvider ldap
    AuthLDAPURL "ldap://127.0.0.1/ou=Persones,dc=exemple,dc=asix?uid?sub?(objectClass=posixAccount)"
    AuthLDAPGroupAttribute memberUid
    AuthLDAPGroupAttributeIsDN off
    Require valid-user
</Directory>

<Directory /var/www/html/intranet/vendes>
    Require ldap-attribute gidNumber=20001
</Directory>

<Directory /var/www/html/intranet/magatzem>
    Require ldap-attribute gidNumber=20002
</Directory>

<Directory /var/www/html/intranet/encarregats>
    Require ldap-group cn=encarregats,ou=Grups,dc=exemple,dc=asix
</Directory>

<Directory /var/www/html/intranet/direccio>
    Require ldap-user aprats
</Directory>

<Directory /var/www/html/intranet/telefons>
    Require ldap-filter &(gidNumber=20001)(telephoneNumber=*)
</Directory>

El primer bloc diu com s'autentica (i ho hereten totes les subcarpetes). Cada subcarpeta només canvia la línia Require: qui hi pot entrar.

Línia RequireQui hi entraPer a què ho fem servir
valid-userqualsevol usuari amb contrasenya correctala intranet general
ldap-attribute gidNumber=20001qui té aquest valor a l'atributgrup principal
ldap-group cn=...qui surt a memberUid del grupgrup secundari
ldap-user aprats jgarciaels usuaris de la llista (separats per espais)persones concretes
ldap-filter ...qui compleix un filtre LDAPcondicions combinades
COMPTE

Grup principal → ldap-attribute; grup secundari → ldap-group. ldap-group només mira les línies memberUid del grup, i els membres per grup principal no hi són.

A ldap-filter, el filtre va sense el parèntesi de fora i sense cometes: &(gidNumber=20001)(telephoneNumber=*). Apache ja hi afegeix els parèntesis.

5Activa-la

$ sudo a2enconf intranet-ldap
$ sudo apache2ctl configtest         # ha de dir Syntax OK
$ sudo systemctl reload apache2

L'avís AH00558: Could not reliably determine the server's fully qualified domain name no és un error.

6Prova-ho

Al navegador del client: http://192.168.50.10/intranet/. Et demana usuari i contrasenya. Per provar amb un altre usuari, fes servir una finestra privada: el navegador recorda l'últim.

És més ràpid provar des del terminal del client amb curl, que només mostra el codi de resposta: 200 ha entrat, 401 no.

$ curl -s -o /dev/null -w "%{http_code}\n" -u aprats http://192.168.50.10/intranet/vendes/
Zonaapratsjgarciamserra
/intranet/200200200
/intranet/vendes/200200401
/intranet/magatzem/401401200
/intranet/encarregats/200401200
/intranet/direccio/200401401
/intranet/telefons/401200401

L'escaner rep 401 a tot arreu: és a ou=Serveis, fora d'on busca Apache.

COMPTE

Apache recorda uns minuts les comprovacions que ha fet. Si canvies alguna cosa al directori (afegeixes algú a un grup) i Apache no ho nota: sudo systemctl restart apache2.

7Mira el registre

Al servidor, deixa el registre obert mentre proves:

$ sudo tail -f /var/log/apache2/error.log
MissatgeQuè ha passat

8Protegeix la contrasenya amb HTTPS

Amb HTTP, el navegador envia l'usuari i la contrasenya només codificats, no xifrats. Qualsevol que vegi el trànsit els pot llegir:

$ curl -sv -u aprats http://192.168.50.10/intranet/ -o /dev/null 2>&1 | grep Authorization
> Authorization: Basic YXByYXRzOlBhdGF0YTEyMw==
$ echo YXByYXRzOlBhdGF0YTEyMw== | base64 -d
aprats:Patata123

Ubuntu porta preparat un lloc web HTTPS amb un certificat de prova. Al servidor:

$ sudo a2enmod ssl
$ sudo a2ensite default-ssl
$ sudo systemctl reload apache2

I perquè la intranet no s'obri mai per HTTP, una redirecció. Edita /etc/apache2/sites-available/000-default.conf i, abans de </VirtualHost>, afegeix:

Redirect permanent /intranet https://192.168.50.10/intranet
$ sudo systemctl reload apache2
$ curl -s -o /dev/null -w "%{http_code} %{redirect_url}\n" http://192.168.50.10/intranet/
301 https://192.168.50.10/intranet/

El navegador avisarà que el certificat no és de confiança: és normal, és un certificat de prova. Amb curl, l'opció -k l'accepta.
