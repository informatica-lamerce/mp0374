01

Per què GNU/Linux, i per què a ASIX

Per a un tècnic de sistemes, Linux no és una alternativa a res: és l'entorn de treball per defecte.

Segurament ja heu tocat alguna distribució. El que potser no heu vist encara és fins a quin punt tot allò que administrareu professionalment corre sobre un nucli Linux.

  • Servidors i núvol. La immensa majoria de servidors web del món corren Linux, i les tres grans plataformes de núvol (AWS, Azure i Google Cloud) l'ofereixen com a sistema per defecte.
  • Contenidors. Docker i Kubernetes són, literalment, tecnologia del nucli Linux: namespaces i cgroups. Sense Linux no hi ha contenidors.
  • Dispositius. Android és Linux. Els encaminadors, les televisions, els punts d'accés i bona part de l'electrònica industrial, també.
  • Supercomputació. Els 500 ordinadors més potents del planeta funcionen tots amb Linux.

A això s'hi suma el que us afecta cada dia com a administradors: cost de llicència zero, accés complet al sistema, tot automatitzable des de la línia d'ordres i una traçabilitat total del que passa a la màquina.

EL QUE ES SUPOSA QUE JA SABEU

Aquest material no explica què és un sistema operatiu ni què és una carpeta. Assumeix que ja teniu la base i que el que necessiteu ara és el com: com s'instal·la, com s'arrenca, com es configura i com es manté una màquina GNU/Linux amb criteri professional.

03

Programari lliure, codi obert i llicències

Dos moviments que es confonen contínuament i que no són el mateix.

Com hi vam arribar

AnyFet
1983Richard Stallman anuncia el projecte GNU, un sistema operatiu compatible amb UNIX però lliure. GNU és un acrònim recursiu: GNU's Not UNIX.
1985Es funda la Free Software Foundation per donar cobertura legal i tècnica al projecte.
1989Apareix la llicència GPL i el concepte de copyleft.
1991Linus Torvalds publica un nucli funcional, Linux, i el distribueix sota GPL. GNU tenia tot el sistema excepte el nucli; Linux tenia el nucli i res més. Encaixaven.
1998Netscape allibera el codi del seu navegador. Neix el terme open source i l'Open Source Initiative.
EL NUCLI QUE NO VA SER

GNU tenia el seu propi nucli en desenvolupament, el Hurd, que mai va acabar de quallar per problemes tècnics i de coordinació. Encara existeix i hi ha distribucions que l'utilitzen, però és marginal. Sense aquell encallament, avui potser no parlaríem de Linux.

Les quatre llibertats

La FSF defineix el programari lliure per allò que permet fer, no pel preu. Es numeren des de zero, com als programadors els agrada:

  1. 0
    Executar el programa per a qualsevol propòsit.
  2. 1
    Estudiar com funciona i adaptar-lo a les vostres necessitats. Requereix accés al codi font.
  3. 2
    Redistribuir còpies per ajudar altres persones.
  4. 3
    Millorar-lo i publicar les millores perquè se'n beneficiï tothom. També requereix accés al codi font.
GRATIS NO ÉS LLIURE

En anglès free vol dir «lliure» i «gratuït» alhora, i això genera confusió permanent. Hi ha programari gratuït que no és lliure de cap manera: un antivirus gratuït no us deixa veure ni modificar el seu codi. I hi ha programari lliure que es ven: Red Hat Enterprise Linux es cobra, i és lliure.

Copyleft: girar el copyright del revés

El copyright convencional reserva els drets a l'autor. El copyleft fa servir el mateix mecanisme legal per garantir el contrari: qualsevol pot copiar i modificar, amb la condició que les modificacions es distribueixin amb les mateixes llibertats. No és domini públic, on es pot fer literalment el que es vulgui, inclòs tancar el codi.

Tècnicament se superposen gairebé del tot; el que canvia és el motiu.

Gairebé tota llicència lliure és també de codi obert. A l'inrevés no sempre: hi ha llicències aprovades per l'OSI que la FSF no considera lliures perquè restringeixen algun ús. I hi ha llicències recents molt populars —les anomenades source available— que deixen veure el codi però prohibeixen competir amb el proveïdor: no són ni una cosa ni l'altra.

04

Distribucions

Nucli + utilitats + escriptori + gestor de paquets + una manera de mantenir-ho tot.

Una distribució agrupa el nucli, les eines de sistema, un instal·lador, un conjunt d'aplicacions i —sobretot— una infraestructura de repositoris i actualitzacions. El que realment distingeix unes distribucions d'altres és el format de paquet, el ritme d'actualització i qui respon quan alguna cosa es trenca.

Les famílies

BSD NO ÉS LINUX

FreeBSD, OpenBSD i NetBSD descendeixen directament del UNIX de Berkeley i tenen nucli propi, no el de Linux. No són distribucions de Linux: són sistemes operatius diferents, amb llicència BSD permissiva en comptes de GPL. macOS n'incorpora components.

Ritmes d'actualització

  • Versions fixes. Un llançament cada cert temps amb un conjunt de paquets congelat. Debian, Ubuntu, RHEL.
  • LTS. Versions de suport llarg. Ubuntu en treu una cada dos anys a l'abril amb 5 anys de manteniment estàndard, ampliables a 10 o més amb Ubuntu Pro. És el que s'instal·la a producció.
  • Intermèdies. Cada sis mesos, amb 9 mesos de suport. Serveixen per provar novetats, no per a servidors.
  • Rolling release. No hi ha versions: el sistema s'actualitza contínuament. Arch, openSUSE Tumbleweed.

Formes d'arribar al sistema

  • Live. El sistema arrenca des del USB sense tocar el disc. Serveix per provar-lo, per rescatar dades i per reparar arrencades. Els instal·ladors d'Ubuntu són live.
  • Netinstall. Imatge mínima que descarrega la resta durant la instal·lació.
  • Immutables. El sistema base és de només lectura i s'actualitza en bloc; les aplicacions van en contenidors. Fedora Silverblue, Ubuntu Core, SteamOS.
  • WSL. Ubuntu executant-se dins de Windows. Molt útil per a desenvolupament, però no substitueix administrar una màquina real.
LA VERSIÓ D'AQUEST BLOC

Ubuntu 24.04 LTS «Noble Numbat», publicada l'abril de 2024, amb suport estàndard fins al juny de 2029. És la versió sobre la qual estan fets els exemples i les pràctiques d'aquesta introducció.

Existeix ja Ubuntu 26.04 LTS «Resolute Raccoon», de l'abril de 2026. Aquí es manté la 24.04 perquè continua plenament suportada i és la que trobareu instal·lada a la immensa majoria de parcs corporatius.

05

Sistemes de fitxers

On es decideixen el rendiment, la integritat de les dades i si podreu recuperar-les.

Journaling

Un sistema de fitxers amb registre per diari anota el que està a punt de fer abans de fer-ho. Si hi ha una apagada a mitja escriptura, en arrencar es consulta el diari i es deixa el sistema en un estat coherent en segons, en comptes d'haver de revisar tot el disc. Tots els sistemes de fitxers de Linux d'ús general en tenen.

LA COMPATIBILITAT NO VA ALS DOS SENTITS

Linux llegeix i escriu NTFS, exFAT i FAT sense instal·lar res. Windows, en canvi, no reconeix ext4 ni btrfs de forma nativa: cal programari de tercers.

I hi ha una raó de fons per no posar mai /home en NTFS: els permisos POSIX (propietari, grup, altres) no hi tenen equivalent real, i els enllaços simbòlics i els fitxers ocults es comporten de manera diferent. Per compartir dades entre els dos sistemes, useu una partició NTFS separada només per a documents.

Xifratge

  • LUKS és el mecanisme estàndard a Linux. Xifra el dispositiu de blocs sencer amb AES-256 XTS per sota del sistema de fitxers. És l'opció recomanada i la que ofereix l'instal·lador d'Ubuntu.
  • fscrypt xifra directoris concrets dins d'ext4. Està disponible, però Canonical no el dona per oficialment suportat.
  • eCryptfs, que xifrava el directori personal, està obsolet. Ubuntu va retirar l'opció de l'instal·lador a la 18.04 i no se'n recomana l'ús.
$ lsblk -f                  # arbre de discos amb sistema de fitxers i UUID
$ df -hT                    # espai lliure i tipus per punt de muntatge
$ sudo blkid                # UUID i tipus de cada partició
$ du -sh /var/log           # què ocupa un directori

EL LÍMIT DE LES QUATRE PARTICIONS

Trobareu molt material que explica que un disc només admet quatre particions primàries i que això complica instal·lar Linux al costat de Windows. És cert només amb taula MBR. Qualsevol equip fabricat des de fa més de deu anys arrenca en UEFI amb GPT i aquesta limitació desapareix.

Comproveu en quin mode esteu: si existeix /sys/firmware/efi, esteu en UEFI.

L'esquema que farem servir

ParticióSistema de fitxersMidaPer a què
/boot/efi (ESP)FAT32512 MiBCarregadors d'arrencada. Es comparteix entre tots els sistemes del disc.
/ (arrel)ext430–50 GiBSistema i aplicacions

swap—Fitxer, no particióUbuntu crea /swapfile. Només cal partició si voleu hibernar.

Separar /home és precisament el que demana l'enunciat del projecte, i el motiu és pràctic: el dia que reinstal·leu o canvieu de distribució, les dades i la configuració de l'usuari es queden on són.

Punts de muntatge i fstab

A Linux no hi ha lletres d'unitat. Cada sistema de fitxers es munta en un directori de l'arbre únic que penja de /. El fitxer /etc/fstab declara què s'ha de muntar automàticament en arrencar. Sempre per UUID, mai per /dev/sda1: els noms de dispositiu poden canviar d'ordre entre arrencades.

$ lsblk                                  # estructura de discos i particions
$ sudo fdisk -l /dev/sda                 # detall de la taula de particions
$ ls /sys/firmware/efi && echo UEFI      # en quin mode hem arrencat
$ cat /etc/fstab                         # muntatges automàtics
$ sudo mount -a                          # aplica fstab sense reiniciar (provar sempre!)
LVM

El gestor de volums lògics posa una capa entre els discos i les particions: podeu ampliar un volum en calent, repartir-lo entre diversos discos o fer-ne instantànies. A servidors és l'estàndard. Per a l'escriptori del projecte no cal, però convé que en sapigueu l'existència.

07

El gestor d'arrencada GRUB2

El menú que surt en engegar. Sabreu configurar-lo i, el que és més important, reparar-lo.

El GRUB2 és el que carrega el nucli. En UEFI s'instal·la com a fitxer .efi dins de la partició ESP; en equips antics amb BIOS, com a codi dins del MBR. Es posa sol durant la instal·lació d'Ubuntu i normalment només caldrà tocar-lo per canviar-ne l'aspecte o per recuperar-lo.

Els fitxers

Fitxer o directoriQuè ésS'edita?
/boot/grub/grub.cfgEl menú real que llegeix el GRUB en arrencarNo. Es genera i se sobreescriu
/etc/default/grubOpcions generals: temps d'espera, entrada per defecte, paràmetres del nucliSí, és el fitxer habitual
/etc/grub.d/Scripts que detecten sistemes i generen les entradesSí, per a canvis avançats
/boot/grub/themes/Temes visuals i imatges de fonsSí

Els scripts de /etc/grub.d/ s'executen per ordre alfabètic, i d'aquí ve el número del nom. Els habituals són 10_linux (detecta els Linux instal·lats), 30_os-prober (detecta Windows i altres sistemes) i 40_custom (entrades vostres). Per fer que Windows aparegui abans que Ubuntu, es reanomena 30_os-prober a un número més baix, per exemple 09_os-prober.

ATENCIÓ: OS-PROBER VE DESACTIVAT

Des del 2021, per motius de seguretat, el GRUB porta os-prober desactivat per defecte. Si instal·leu Ubuntu al costat de Windows i el Windows no surt al menú, gairebé sempre és això. Afegiu a /etc/default/grub:

GRUB_DISABLE_OS_PROBER=false — i després sudo update-grub.

Configuració habitual

$ sudo nano /etc/default/grub

  GRUB_DEFAULT=0                  # entrada per defecte (0 = la primera)
  GRUB_TIMEOUT=10                 # segons d'espera
  GRUB_TIMEOUT_STYLE=menu         # mostra sempre el menú
  GRUB_DISABLE_OS_PROBER=false    # detecta Windows i altres sistemes
  GRUB_CMDLINE_LINUX_DEFAULT="quiet splash"

$ sudo update-grub                 # regenera grub.cfg — imprescindible

Cap canvi té efecte fins que no s'executa update-grub.

Aspecte del menú

$ sudo apt install grub2-themes-ubuntu-mate desktop-base
$ sudo nano /usr/share/desktop-base/grub_background.sh
  # WALLPAPER, COLOR_NORMAL i COLOR_HIGHLIGHT
$ sudo update-grub

# Alternativa gràfica, molt més còmoda:
$ sudo add-apt-repository ppa:danielrichter2007/grub-customizer
$ sudo apt update && sudo apt install grub-customizer

Protegir el menú amb contrasenya

$ grub-mkpasswd-pbkdf2            # genera el resum grub.pbkdf2.sha512...
$ sudo nano /etc/grub.d/00_header  # afegiu al final:

  cat << EOF
  set superusers="administrador"
  password_pbkdf2 administrador grub.pbkdf2.sha512....el resum...
  EOF

# Perquè es pugui arrencar sense contrasenya però no editar les entrades,
# a /etc/grub.d/10_linux:
  CLASS="--class gnu-linux --class gnu --class os --unrestricted"

$ sudo update-grub

Quan el GRUB desapareix

Passa típicament després d'instal·lar Windows, que es reclama la prioritat d'arrencada. La reparació es fa des d'un USB live d'Ubuntu:

# Opció A — automàtica, la recomanada
$ sudo add-apt-repository ppa:yannubuntu/boot-repair
$ sudo apt update && sudo apt install -y boot-repair
$ boot-repair                       # "Reparació recomanada"

# Opció B — manual amb chroot (UEFI)
$ sudo mount /dev/sdaX /mnt         # X = partició arrel
$ sudo mount /dev/sdaY /mnt/boot/efi # Y = partició EFI
$ for d in dev proc sys run; do sudo mount --bind /$d /mnt/$d; done
$ sudo chroot /mnt
# grub-install /dev/sda && update-grub
# exit
SECURE BOOT

Amb Secure Boot activat, el firmware només executa carregadors signats. Ubuntu ho resol amb un petit programa signat per Microsoft, el shim, que al seu torn valida el GRUB. Funciona sense fer res. On sí que dona feina és en instal·lar controladors de nucli no signats —típicament els de NVIDIA—: el sistema us demanarà inscriure una clau MOK reiniciant. Si no ho feu, el controlador no carrega.

08

Arrencada dual amb Windows

Es pot fer i es fa. També és la manera més ràpida de deixar un equip sense arrencar.

La documentació oficial d'Ubuntu recomana obertament no fer arrencada dual i, en comptes d'això, instal·lar Linux de forma nativa i virtualitzar l'altre sistema. El motiu és que les actualitzacions de Windows sobreescriuen l'ordre d'arrencada amb certa alegria. Tot i així, us el trobareu muntat a molts equips i heu de saber-lo gestionar.

L'ordre importa

Primer Windows, després Ubuntu. L'instal·lador de Windows tendeix a apropiar-se del disc sencer i a ignorar el que hi hagi; el d'Ubuntu detecta el que ja hi és i s'hi adapta.

Abans de començar

  1. Feu còpia de seguretat. Sona obvi i és el pas que més es salta.
  2. Desactiveu l'inici ràpid de Windows. El Fast Startup no apaga l'equip: hiberna el nucli. La partició NTFS queda marcada com a «en ús» i Linux la muntarà només de lectura o es negarà a muntar-la. Panell de control → Opcions d'energia → Comportament dels botons d'inici → desmarqueu «Activa l'inici ràpid».
  3. Suspeneu BitLocker i guardeu-ne la clau de recuperació. Tocar les particions o l'ordre d'arrencada amb BitLocker actiu us pot deixar fora de Windows.
  4. Reduïu la partició de Windows des de Windows, amb Administració de discos. És més segur que fer-ho des de fora.
  5. Comproveu que arrenqueu en UEFI i que tots dos sistemes fan servir el mateix mode. Barrejar UEFI i llegat en un mateix disc no funciona.
EL RELLOTGE QUE VA DUES HORES ENDARRERIT

Linux assumeix que el rellotge del maquinari va en UTC; Windows assumeix que va en hora local. En arrencada dual, l'hora balla cada vegada que canvieu de sistema. La solució neta és dir-li a Linux que faci com Windows:

timedatectl set-local-rtc 1 --adjust-system-clock

Durant i després

  • Els dos sistemes comparteixen una sola partició ESP. No en creeu una segona.
  • Trieu «Instal·la Ubuntu al costat de Windows» si voleu el camí curt, o el particionat manual si voleu decidir vosaltres les mides.
  • Si en acabar no apareix Windows al menú, és os-prober: el trobareu resolt a la secció anterior.
  • Si una actualització de Windows us deixa sense GRUB, arrenqueu amb el USB live i passeu-hi el boot-repair.
EL QUE FAREM AL PROJECTE

Treballarem amb màquines virtuals. Us dona exactament els mateixos conceptes —particions, GRUB, gestor d'arrencada, convivència de dos sistemes— sense arriscar l'equip de l'aula, i podeu tornar enrere amb una instantània quan una prova surti malament.

Instal·lar Ubuntu 24.04 LTS

Del lloc de descàrrega a un sistema actualitzat i amb controladors.

1. Triar la versió

  • LTS — abril dels anys parells, 5 anys de manteniment estàndard. És el que va a producció i el que farem servir.
  • Intermèdia — cada sis mesos, 9 mesos de suport. Per provar novetats.
  • Arquitectura — amd64 (64 bits). Ubuntu ja no publica imatges de 32 bits per a escriptori.
  • Edició — Desktop o Server. Per al projecte, Desktop.

Requisits mínims d'Ubuntu Desktop 24.04

Processador de doble nucli a 2 GHz, 4 GiB de RAM i 25 GB de disc. Per a la màquina virtual del projecte convé anar més amunt: 4 GiB de RAM i 40 GB de disc si l'amfitrió ho permet.

2. Verificar la descàrrega

No és un tràmit: és comprovar que la imatge no s'ha corromput i que ve realment de Canonical. Descarregueu la ISO, el fitxer SHA256SUMS i la seva signatura.

# Suma de verificació
$ sha256sum ubuntu-24.04.3-desktop-amd64.iso
$ sha256sum -c SHA256SUMS 2>&1 | grep OK

# Signatura: confirma que la llista de sumes és autèntica
$ gpg --keyid-format long --verify SHA256SUMS.gpg SHA256SUMS

La suma comprova la integritat. La signatura comprova la procedència. Són coses diferents i calen totes dues.

3. Preparar el suport

  • En màquina virtual (VirtualBox, VMware, Isard): la ISO es connecta directament a la unitat òptica virtual. No cal gravar res.
  • En màquina física: USB d'arrencada amb Rufus, balenaEtcher, el Creador de discos d'inici d'Ubuntu o Ventoy.
  • Els CD i DVD han desaparegut del procés. Si trobeu documentació que us diu de gravar la ISO en un DVD, és antiga.

4. L'instal·lador

Ubuntu 24.04 estrena instal·lador. Passos, en ordre:

  1. Idioma i opcions d'accessibilitat
  2. Distribució de teclat
  3. Connexió de xarxa
  4. Provar Ubuntu o instal·lar-lo
  5. Instal·lació interactiva o automatitzada amb un fitxer de configuració
  6. Selecció ampliada o per defecte — la per defecte instal·la el mínim; l'ampliada afegeix ofimàtica i utilitats
  7. Programari de tercers — controladors privatius i còdecs multimèdia. Marqueu-ho si voleu la màquina operativa des del primer minut
  8. Tipus d'instal·lació — esborrar el disc, instal·lar al costat d'un altre sistema o particionat manual
  9. Xifratge — LUKS amb contrasenya, o suportat per TPM (encara experimental)
  10. Compte d'usuari i nom de l'equip
  11. Zona horària
PARTICIONAT MANUAL

És l'opció que demana el projecte, perquè és l'única que permet separar /home. Trieu «Something else» / «Configuració manual» i definiu l'ESP, l'arrel i /home tal com s'indica a la secció 6.

5. Després d'instal·lar

$ sudo apt update && sudo apt full-upgrade -y   # posar-ho tot al dia
$ ubuntu-drivers devices                        # controladors disponibles
$ sudo ubuntu-drivers install                   # instal·la els recomanats
$ sudo apt install ubuntu-restricted-extras     # còdecs, tipus de lletra, Java
$ lsb_release -a && uname -r                    # comprovació final
$ sudo reboot

A la configuració de Programari i actualitzacions podreu ajustar quins tipus d'actualització s'instal·len, cada quant es comprova si n'hi ha, com es notifiquen les de seguretat i si el sistema ha d'avisar de noves versions d'Ubuntu (i si només de les LTS). És exactament el que demana l'apartat A del projecte.

DESPLEGAMENT MASSIU

Instal·lar cinquanta màquines a mà no és feina d'un administrador. Ubuntu permet l'autoinstall: un fitxer YAML amb totes les respostes que l'instal·lador aplica sol. És el camí natural cap a la gestió de parcs.

Els quatre components d'Ubuntu

  • universe — lliure, mantingut per la comunitat
  • restricted — controladors privatius que Canonical dona suport
  • multiverse — programari amb restriccions legals o de llicència

Repositoris: el format ha canviat

Des de la 24.04, Ubuntu ja no fa servir el vell /etc/apt/sources.list d'una línia per repositori. Ara el format per defecte és deb822, en fitxers .sources amb parelles clau–valor, molt més llegibles. El format antic continua funcionant, però està marcat com a obsolet.

$ cat /etc/apt/sources.list.d/ubuntu.sources

  Types: deb
  URIs: http://es.archive.ubuntu.com/ubuntu/
  Suites: noble noble-updates noble-backports
  Components: main restricted universe multiverse
  Signed-By: /usr/share/keyrings/ubuntu-archive-keyring.gpg

$ sudo apt modernize-sources     # converteix el format antic al nou

Afegir repositoris de tercers

Un PPA és un repositori personal allotjat a Launchpad. Són còmodes i molt habituals, però qui els manté no respon davant de ningú: no n'afegiu cap que no us inspiri confiança.

$ sudo add-apt-repository ppa:usuari/repositori
$ sudo apt update && sudo apt install paquet

$ sudo add-apt-repository --remove ppa:usuari/repositori
$ sudo apt install ppa-purge && sudo ppa-purge ppa:usuari/repositori

Per a repositoris externs que no siguin PPA, la clau de signatura va a /etc/apt/keyrings/ i es referencia amb Signed-By. L'ordre apt-key està obsoleta i no s'ha de fer servir:

$ sudo install -d -m 0755 /etc/apt/keyrings
$ curl -fsSL https://exemple.com/clau.asc \
    | sudo tee /etc/apt/keyrings/exemple.asc > /dev/null

$ sudo tee /etc/apt/sources.list.d/exemple.sources > /dev/null <<'EOF'
  Types: deb
  URIs: https://exemple.com/apt
  Suites: noble
  Components: main
  Architectures: amd64
  Signed-By: /etc/apt/keyrings/exemple.asc
  EOF

$ sudo apt update

Un fitxer .deb solt

$ sudo apt install ./programa.deb    # correcte: resol dependències
$ sudo dpkg -i programa.deb          # instal·la, però pot deixar-les trencades
$ sudo apt --fix-broken install      # reparació si heu fet servir dpkg

La barra de ./ és obligatòria: sense ella, APT buscaria un paquet anomenat «programa.deb» als repositoris.

Snap

Format de Canonical, preinstal·lat a Ubuntu. Cada snap porta les seves dependències, s'executa confinat per AppArmor i s'actualitza sol en segon pla. Firefox ve com a snap des de la 22.04.

$ snap find telegram
$ sudo snap install telegram-desktop
$ sudo snap install codi --classic        # classic = sense confinament
$ snap list && snap info telegram-desktop
$ sudo snap refresh                       # actualitza ara
$ sudo snap refresh --hold=24h            # atura les actualitzacions automàtiques
$ sudo snap revert telegram-desktop       # torna a la revisió anterior
$ sudo snap remove --purge telegram-desktop

Els canals stable, candidate, beta i edge permeten triar quina maduresa voleu: --channel=beta.

Flatpak

Alternativa de la comunitat, per defecte a Fedora. Sempre en sandbox, amb runtimes compartits entre aplicacions i permisos gestionats per portals. A Ubuntu no ve instal·lat i cal afegir-lo:

$ sudo apt install flatpak gnome-software-plugin-flatpak
$ sudo flatpak remote-add --if-not-exists flathub \
    https://dl.flathub.org/repo/flathub.flatpakrepo
$ sudo reboot

$ flatpak search gimp
$ flatpak install flathub org.gimp.GIMP
$ flatpak list && flatpak update
$ flatpak uninstall --unused        # neteja runtimes orfes

AppImage

Un únic fitxer executable que ho porta tot dins. No s'instal·la: es descarrega, es marca com a executable i s'executa. No hi ha desinstal·lació perquè no hi ha instal·lació, i tampoc hi ha actualitzacions automàtiques.

$ chmod +x Programa-1.0-x86_64.AppImage
$ ./Programa-1.0-x86_64.AppImage

# Ubuntu 24.04 necessita FUSE 2 per a molts AppImage:
$ sudo apt install libfuse2t64

# Per integrar-los al menú i gestionar-los:
$ flatpak install flathub io.github.prateekmedia.appimagepool

Compilar des del codi font

$ sudo apt install build-essential
$ tar xzf programa-1.0.tar.gz && cd programa-1.0
$ ./configure && make && sudo make install

Últim recurs: el gestor de paquets no sap que això existeix, no s'actualitzarà i desinstal·lar-ho és feina manual.

CRITERI DE DECISIÓ

1. Mireu primer si és als repositoris: apt search. És el més integrat, el més lleuger i el que s'actualitza amb el sistema.
2. Si no hi és, o la versió és massa antiga, aneu a Flatpak o Snap.
3. AppImage per provar una cosa sense deixar rastre.
4. Compilar, només si no queda cap altra opció.

Eines gràfiques

  • App Center — la botiga d'Ubuntu 24.04. Mostra snaps i, si instal·leu el connector, també flatpaks i paquets deb.
  • Synaptic — sudo apt install synaptic. Gestió avançada d'APT: filtres, versions concretes, bloqueig de paquets, dependències inverses. Res de snaps.
  • Programari i actualitzacions — repositoris, controladors addicionals i política d'actualitzacions.

Configuració de xarxa

NetworkManager a l'escriptori, netplan per sota, i sempre una ordre per comprovar-ho.

A Ubuntu Desktop qui mana és el NetworkManager. Ubuntu hi afegeix netplan, una capa de configuració en YAML que descriu la xarxa i la tradueix al motor corresponent: NetworkManager a l'escriptori, systemd-networkd al servidor.

Perfils de connexió

Cada connexió és un perfil amb nom propi. Es poden tenir-ne diversos sobre la mateixa targeta i canviar-hi segons on sigui la màquina: un amb DHCP i un altre amb IP fixa per a l'aula, per exemple. Es gestionen des de Configuració → Xarxa, o des del terminal.

$ nmcli connection show                    # perfils existents
$ nmcli device status                      # interfícies i estat

# Crear un perfil amb IP estàtica
$ sudo nmcli connection add type ethernet con-name "Aula209" ifname enp0s3 \
    ipv4.method manual \
    ipv4.addresses 172.16.109.25/16 \
    ipv4.gateway 172.16.55.35 \
    ipv4.dns "172.16.200.120,192.168.0.15" \
    ipv6.method disabled

$ sudo nmcli connection up "Aula209"
$ sudo nmcli connection modify "Aula209" connection.autoconnect yes
$ nmtui                                    # mateixa feina, amb menús

Els quatre paràmetres de sempre

ParàmetreQuè ésExemple
Adreça IPIdentifica l'equip a la xarxa172.16.109.25
MàscaraQuina part és la xarxa i quina l'equip255.255.0.0 = /16
Passarel·laPer on se surt de la xarxa local172.16.55.35
DNSQui tradueix noms a adreces172.16.200.120
CLASSES A, B I C

Encara es diu «màscara de classe B» per dir /16, però les classes van quedar substituïdes per CIDR l'any 1993. El que realment importa és la longitud del prefix: /16 vol dir que els setze primers bits identifiquen la xarxa.

Un error de màscara és la causa més freqüent de «tinc IP però no tinc Internet»: si la passarel·la queda fora del rang que defineix la vostra màscara, l'equip no hi sap arribar.

Diagnòstic, en ordre

$ ip -c a                        # 1. tinc adreça IP?
$ ip r                           # 2. tinc ruta per defecte?
$ ping -c3 172.16.55.35          # 3. arribo a la passarel·la?
$ ping -c3 1.1.1.1               # 4. surto a Internet per IP?
$ resolvectl status              # 5. quins DNS faig servir?
$ dig lamerce.com                # 6. resolc noms?
$ ss -tulpn                      # ports oberts i qui escolta

Si el pas 4 funciona i el 6 no, el problema és el DNS. Aneu de dins cap a fora i no us salteu passos.

ORDRES QUE JA NO TOCA FER SERVIR

ifconfig, route i netstat pertanyen al paquet net-tools, abandonat i no instal·lat per defecte. Els equivalents actuals són ip a, ip r i ss. Per veure una adreça MAC: ip link show.

Usuaris, grups i seguretat local

Qui pot fer què, i durant quant de temps.

On viu la informació

FitxerContingutPermisos

/etc/shadowResums de contrasenya i política de caducitatNomés root
/etc/groupGrups i membresLlegible per tothom
/etc/login.defsValors per defecte en crear usuarisNomés root

Crear i gestionar

$ sudo adduser admin-cognom              # interactiu, crea /home i grup propi
$ sudo usermod -aG sudo admin-cognom     # -a és imprescindible: afegeix sense esborrar
$ sudo addgroup asix-cognom
$ sudo usermod -aG asix-cognom normal-cognom
$ groups normal-cognom && id normal-cognom
$ sudo deluser --remove-home usuari

Oblidar la -a a usermod -G treu l'usuari de tots els altres grups. Si el traieu de sudo, us quedeu fora.

Caducitat de contrasenyes

$ sudo chage -l usuari                       # estat actual
$ sudo chage -M 15 -m 1 -W 3 normal-cognom   # caduca als 15 dies, avisa 3 abans
$ sudo chage -M -1 admin-cognom              # no caduca mai
$ sudo passwd -e normal-cognom               # l'ha de canviar al proper inici

$ sudo nano /etc/login.defs                  # per als usuaris nous
  PASS_MAX_DAYS   90      # el valor per defecte és 99999
  PASS_MIN_DAYS   1
  PASS_WARN_AGE   7

Per defecte el sistema accepta gairebé qualsevol cosa. El mòdul PAM pam_pwquality imposa regles reals:

$ sudo apt install libpam-pwquality
$ sudo nano /etc/pam.d/common-password

     ucredit=-1 lcredit=-1 dcredit=-1 ocredit=-1 \
     reject_username enforce_for_root

XIFRAR EL DIRECTORI PERSONAL: QUÈ ÉS VÀLID AVUI

Trobareu molts manuals que expliquen com xifrar /home amb eCryptfs i ecryptfs-migrate-home. Ubuntu va retirar aquesta opció de l'instal·lador a la 18.04 i la considera obsoleta i sense manteniment. No és el que s'ha de fer avui.

El recomanat és LUKS, xifratge de disc complet, activat durant la instal·lació. Com a alternativa per a directoris concrets hi ha fscrypt, disponible a Ubuntu però sense suport oficial.

# Xifrar un directori concret amb fscrypt
$ sudo apt install fscrypt
$ sudo fscrypt setup
$ mkdir ~/Privat && fscrypt encrypt ~/Privat
$ fscrypt status ~/Privat
$ fscrypt lock ~/Privat && fscrypt unlock ~/Privat
